# 寶箱房規格

分支：`feat/treasure-room`。

## 1. 出現規則

- 每層建層時擲骰：**10%** 機率產生一間寶箱房。
- **保底**：連續 8 層沒出現，下一層（第 9 層）必定出現。計數 `treasure_pity` = 連續沒出現的層數；出現時歸零。
- **Boss 層（`depth % 5 === 0`）不產生**，但計數照常 +1；若保底在 Boss 層觸發，順延到下一個非 Boss 層。
- 計數只在「實際進入新樓層並建層」時更新；同一層回城再回來（解凍／重建同層）沿用原結果，不重擲、不重算。
- `?devDepth` 開的局不讀也不寫計數。
- 該層戰鬥房（`role === 'combat'`）少於 3 間時不產生（計數照 +1，保底順延）。

## 2. 哪間房

- 從 `role === 'combat'` 的房間挑，排除：起點、鑰匙、出口、神殿，以及「最後一間戰鬥房」（它負責保底菁英）。
- 優先挑**死路**（只有一個出入口／在房間圖上度數最小）的房間；同分隨機。
- 房間內**不生成任何怪物與蟲群**；多人人數加成的額外怪也不放進這間。巡邏追擊進房的怪不受限。
- 房間裡放 **3～6 個寶箱**（均勻隨機），在房內空格分散擺放，不擋門口。

## 3. 每個寶箱的掉寶

| 機率 | 內容 |
|---|---|
| 20% | 金幣＋藥水：約等於 **3 隻無名菁英**的金幣與藥水（金幣量 ×3；藥水依菁英掉藥機率擲 3 次）。不含遺物 |
| 50% | 約等於 **1 隻無名菁英**的正常掉寶（金幣、藥水、遺物：`rollRelicDrops(..., 'elite')`） |
| 20% | 約等於 **1 隻具名菁英**的正常掉寶（含具名菁英的掉寶倍率 1.2） |
| 9% | 約等於 **Boss** 掉寶（Boss 寶藏同款：金幣 ×1.5、藥水、Boss 遺物且保底黃色以上） |
| 1% | Boss 掉寶 **＋ 額外 1 件橘色或綠色遺物**（各 50%） |

- 金幣量照該層的深度縮放（沿用現有菁英／Boss 計算）。
- 實作時把「菁英掉寶」「具名菁英掉寶」「Boss 寶藏」抽成可重用的函式，避免複製計算；不得改變原本菁英／Boss 掉寶的數值。

## 4. 開啟

- 走到寶箱旁（約 1.6 內）顯示提示「按 F 開啟」，按 **F** 開啟（與傳送門／救援同一套鄰近提示；多個互動同時可用時，寶箱優先度低於救援、高於傳送門，或依現有優先序擺放並說明）。
- 開啟為瞬間：開箱動畫（蓋子掀開並保持開啟）、音效、寶物噴出（沿用遺物噴出邏輯）。已開的寶箱不能再開。
- **自動模式**：本地英雄在自動駕駛時，房間內沒有威脅就會走過去逐一開啟（不搶在戰鬥中開）。**bot 不開寶箱**。

## 5. 多人

- 任何人打開一個寶箱，**地城中每位活著的英雄（含 bot）各自擲一次**該寶箱的掉寶（同 Boss 寶藏每人一份、個人掉寶 `ownerId` 規則）。bot 的掉寶直接進背包。
- 寶箱房的位置、寶箱位置與開啟狀態由房主決定並同步：
  - 建層：放進 `level` 酬載（選用欄位）。
  - 開啟：隊友送開箱請求（沿用現有 `cmd`／動作管道），房主判定後在世界快照或事件中廣播已開狀態。
- 協定只加選用欄位，向下相容；Room DO 只轉送，**不需** `deploy:room`。
- 多人時保底計數用**房主角色**的計數；隊友的計數不變。

## 6. 提示與外觀

- 第一次有英雄（本地）走進寶箱房：橫幅「發現寶藏室！」＋音效。
- 寶箱模型：以城鎮倉庫寶箱（`StashChestRig`）改出地城版（較暗的木色、金色光暈／點光），開啟後蓋子保持掀開、光暈熄滅。
- 小地圖：寶箱房被探索後顯示寶箱圖示；未開的寶箱標金色、已開標灰色。走進前不提示。

## 7. 存檔（D1 migration）

- 新增欄位：`migrations/0003_treasure_pity.sql`：`ALTER TABLE characters ADD COLUMN treasure_pity INTEGER NOT NULL DEFAULT 0;`
- `shared/character.ts`（`CharacterState`／`CharacterSave`）、`functions/_lib/validate.ts`（選用欄位，缺省時保留伺服器值；範圍 0～50 整數）、角色讀寫 API、`SaveManager`、`Hero` 的匯出／載入都要帶上 `treasure_pity`。舊存檔缺欄位一律當 0。
- P6 交易（`workers/room/src/trade.ts`）寫存檔時**不得**覆蓋或清掉 `treasure_pity`（確認其 UPDATE 不涉及此欄）。
- **部署順序**：`npm run db:migrate:remote` 必須在新版 Pages（合併到 `main`）之前執行。新增欄位有預設值，舊版程式不受影響，所以可以先跑。

## 8. 驗證

- `npm run lint`、`npm run build`、`bun install --frozen-lockfile`；`npm run db:migrate:local`。
- 以暫時的開發手段（不提交）強制寶箱房出現，無介面瀏覽器確認：房內無怪、3～6 個寶箱、F 開啟、動畫、掉寶、小地圖圖示、橫幅；自動模式會去開；bot 不開但有拿到掉寶。
- 以大量模擬（純函式或腳本）驗證五種結果的機率分佈接近 20/50/20/9/1，以及出現率與保底（每層 10%、最多連 8 層沒出現）。
- 存檔：計數會上傳、重新載入後保留；`?devDepth` 不影響計數；交易後計數不變。
- 多人：兩個瀏覽器確認寶箱位置一致、一人開啟雙方都看到已開、雙方各自拿到掉寶。
- 同步更新 `PROJECT_BRIEF.md`（近期動態，註明 migration 0003 與部署順序）與 `docs/p1-setup.md`／`docs/p5-setup.md` 中列出 migration 的地方。
